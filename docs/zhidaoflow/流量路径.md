# 流量路径（熟读纪要）

**一句话：** 在本仓库里，真正被写清楚的「流量」是 XLOOP PARK 的经营流量：人从哪来、在场内怎么被看见、如何被内容/券送到铺位、怎样核销回流、又怎样变成下一次投放。智算云 Token 网关是另一条请求流，不要和客流画在一张经营图上。

来源：`docs/XLOOP_PARK_AI_系统性思维与战略架构白皮书_v0.1.md` / `_v0.5.md` / `_v0.6.md`，以及 `trae/agent-DBLvD5` 的智算云页面。页码式定位改用白皮书章节号。

---

## 1. 先记住两张总图

### 1.1 街区经营流量（主路径）

白皮书把「来了没有、逛得对不对、停得住不住、还会不会再来」写成 **流量链**，但流量链单独转不了钱。钱是在四条链咬合之后才出现的：

```text
                    线上种草（内容场）
                          │
                          ▼
陌生人 ──来──▶ 可识别客群 ──逛──▶ 停留 ──转化──▶ 核销/联单 ──再来──▶ 复访样本
  │               │            │         │              │
  │               ▼            ▼         ▼              ▼
  │            客流感知      动线/导航   券/定价/联票    OneID 回流
  │            （数据场）    （物理场）  （交易链）      （归因层）
  │
  └── 未识别的路过客流：只能进 L0/L1 大屏，进不了增长循环
```

四条价值链（v0.1 §3.2，v0.5 §3.2）：

| 链 | 系统目标 | 飞轮 |
|----|----------|------|
| **流量链** | 来、逛、停、再来 | 客流感知 → 动线优化 → 夜场/活动 → 复访 |
| **内容链** | 生产、分发、到店 | MCN/AIGC → 投流 → 核销 → 商户续费/联营 |
| **交易链** | 转化、客单、联单 | 画像发券 → 动态定价 → 酒店/餐饮/娱乐联票 |
| **资产链** | 租金质量、能耗、存活 | 招商匹配 → 商户帮扶 → 坪效监控 → 汰换 |

XLOOP 的物理锚点（v0.1 §3.2）：

- 三层客流（15 万师生高频 / 5 万居民中频 / 1200 间酒店中额）→ 流量链必须分层，不能一套券打所有人  
- 7#5F 约 5948㎡ MCN → 内容链的物理核  
- 中心广场 + 夜市 + LED → 流量链与内容链的交汇场  
- 3# 教育 / 4# 餐饮酒店 / 7# 娱乐 → 交易链与资产链的业态载体

### 1.2 通用智慧商业 vs XLOOP 原生路径（v0.1 §4.2）

```text
通用街区 AI：   客流 → 会员 → 营销 → 能耗 → （偶尔）内容外包
XLOOP AI 原生： 数据预埋 → MCN产能 → 营销核销 → 客流反哺 → 业态决策
```

读法：XLOOP 不允许「先做完客流大屏再考虑内容」。开业前必须先把数据四肢和 MCN 产能预埋进去，否则客流感知没有执行出口，内容也没有核销入口。

## 2. 流量在系统里经过哪几层

### 2.1 五层递进：从看见到赚到（v0.1 §2.1）

```text
L1 感知层   CV / IoT / POS / 会员 / 内容互动     ← 流量进入系统的第一口
L2 语义层   OneID、轨迹、画像、业态标签         ← 匿名人头变成可分层样本
L3 决策层   招商、调铺、定价、营销、排班、能耗   ← 决定把流量送到哪
L4 执行层   券、工单、LED、直播、安保、补货     ← 流量变成动作
L5 归因层   核销、坪效、ROI、存活率、能耗节省   ← 证明这条流量值不值得再买
```

白皮书的硬规则：**缺感知则决策无输入；缺执行则洞察变装饰；缺归因则无法证明 ROI。**  
客流热力如果不能驱动调铺 / 排班 / 投放，就不上线（闭环原则）。

成熟度目标（v0.1 §2.3，v0.5 §2.3）：

- 开业前避免停在 L0 展示型  
- 开业前至少 L1 感知型（客流数字准）  
- **开业锚定 L2 执行型**（券/LED/工单能下发）  
- 12 个月内冲刺 L3 经营型（内容投放能归因到坪效与续约）

### 2.2 三层能力架构：流量的上下行（v0.1 §3.1）

```text
应用层    AI内容矩阵 / 智能营销 / 客服 / 体验AI / 夜经济AI     ← 人能感到的触点
能力层    客流洞察 / 招商AI / 商户赋能 / MCN直播 / 能耗AI / BI ← 经营在调度流量
基础层    5G / CV / 统一POS会员 / 数据中台 / 智能硬件         ← 流量信号的四肢
                 ↑
        核销 / 行为 / 能耗 / 内容互动 回流
```

关键分叉：通用方案把招商、物业、营销、安防并列；XLOOP 必须把 **MCN/内容生产** 提升到与客流洞察同级的中台。否则流量链只有「场内人头」，没有「来之前的注意力」。

### 2.3 三场必须被同一套编排看见（v0.6 §6）

```text
物理场：动线、铺位、广场、停车、夜市
内容场：直播间、LED、短视频场景、数字人触点
数据场：热力、画像、交易、能耗、工单
```

三种经典断链（v0.6 §6.2），也是流量路径的故障模式：

1. 物理场很热闹，内容场在别处带货 → 线上流量不到店  
2. 数据场有热力，物理场调不了铺 → 感知停在 L1  
3. 内容场爆了，核销场接不住 → 交易链断裂，钱停在观看数

每个关键空间都要有可触发接口（发券、导流、播报、调光、派单），每个接口产生的行为必须回到数据场（界面原则 + 回流原则）。夜经济主战场（广场+夜市）优先级与一楼同等，因为 When（夜间）× Where（户外）是增量最大处。

## 3. 人怎么被分层，流量怎么被分流

### 3.1 Who：匿名流量 → 可学习样本（v0.6 §3.1）

| 维度 | 过去 | AI 之后 |
|------|------|---------|
| 身份 | 路过的人 | 可分层客群（师生 / 居民 / 酒店 / 家长） |
| 价值 | 人头与客单 | 生命周期价值 + 可实验性 |
| 关系 | 单次交易 | 可触达、可召回、可内容种草 |

15 万师生的正确读法是 **研发样本库**，不是宣传口径里的「巨大客流」。高频小额客群的战略价值是：谁拥有稳定样本，谁就能更快迭代发券、定价、内容和业态假设。

商户必须同时是数据节点、内容节点、体验节点。谁不进这张网，谁就拿不到精准流量（v0.6 §3.2）。这会倒逼招商合同写成「租金 + 数据义务 + 内容协同」。

主体操作系统公式（v0.6 §3.5）：

```text
编排者（运营） × 节点（商户） × 样本（客群） × 产能（MCN）
= AI 街区的主体操作系统
```

缺任何一项，流量都会退化成单点工具：有热力无券，有券无核销，有内容无职人。

### 3.2 按盘分流，而不是平均撒流量

| 客群 | 频次/价值 | 流量策略入口 | 典型出口 |
|------|-----------|--------------|----------|
| 师生 | 高频小额 | 身份识别、学期节律、反潮汐 | 学生券、自习室、夜场、KTV/电竞 |
| 居民 | 中频 | 复访与家庭场景 | 夜市、餐饮、日常零售 |
| 酒店 | 中额、过路 | 联票与停留窗口 | 餐饮/娱乐联票，ADR 与餐饮客流互哺 |
| 家长探访 | 低频高意向 | 教育集群触发 | 餐饮+酒店+伴手礼套餐（转化口径 8–12%） |

4# 餐饮+酒店的文档口径（v0.1 §5.3）：学生身份券核销率 25%+、复购 +20%；酒店-商户联票：酒店 ADR +5%，餐饮客流 +15%。这些数字是白皮书待校准假设，不是已验证结果。

## 4. 三条业务循环：流量如何变成经营动作

开业前 9 个月的优先级（v0.1 §3.3）：先打通 **循环 B 的内容侧** 与 **循环 A 的能耗/感知侧**；循环 C 的招商 AI 必须同步启动，否则开业组合本身不可逆。

### 4.1 循环 B｜增长循环（增收，流量主循环）

```text
画像分层 → 内容 / 券 / 联票 → 到店核销 → 客单与复购回流 → 再训练
```

这是「注意力 → 交易」的完整路径。v0.6 把 Why 改写成：在人、货、场之间持续降低错配，提高每一次注意力转化为交易与复购的概率。五类错配对应五条干预：

| 错配 | 表现 | 流量上的干预 |
|------|------|----------------|
| 人—场 | 来了逛不对、停不久 | 动线、导航、停留干预 |
| 人—货 | 看见的不是想要的 | 画像、推荐、联票、动态货盘 |
| 货—场 | 好品牌放错楼层/时段 | 招商与调铺 |
| 时—需 | 寒暑假空城、夜场过载 | 反潮汐、峰值调度 |
| 内—外 | 线上种草到不了店 | 内容—核销闭环 |

内容链的外部证据（v0.5，不作单因子因果）：

- 天虹：种草 → 团购 → 门店交付；总部统一货盘/核销  
- 万达 520：视频号联播 + 小程序/支付核销，观看、客流、销售同时出现  
- 「一日店长」：内容+券后客流 +40%、核销 94%（平台侧口径）

XLOOP 动作：5948㎡ MCN 产出「街区主号 + 商户职人 + KOL 入驻」三层矩阵，同时必须建 **排期—货盘—核销—分账中台**，不能只做 AIGC 拍视频。

### 4.2 循环 A｜场运循环（降本 + 体验，流量的物理侧）

```text
CV / 能耗 / 停车 → 实时调度 → 工单 / 调光 / 排班 → 能耗与投诉指标回流
```

客流洞察的 P0 产出不是大屏，而是 **调铺建议 + 夜场安保预案 + 招商画像**（v0.5 湖滨启示）。

感知最低完备集（v0.1 §6.1）：

1. 网络：光纤 + 5G 微基站  
2. 视觉：入口、扶梯、广场、停车场点位预埋  
3. 交易身份：统一收银 + 会员（OneID 前提）  
4. 数据中台：指标、API、权限、审计  
5. 智能硬件：LED、能耗分户、停车

能耗必须和客流热力联动（太古汇/万科里类）：人流驱动分区供冷，否则「流量路径」在场运侧是断的。

### 4.3 循环 C｜资产循环（租金质量，流量的供给侧）

```text
招商匹配 → 开业辅导 → 坪效监控 → 帮扶或汰换 → 品牌库进化
```

流量再准，铺位组合错了也会空转。湖滨用画像改「湖滨88」国潮定位，说明客流标签要和招商标签共用一套体系。

## 5. 端到端走一遍（把链串成一条可执行路径）

下面按一个真实客人的时间顺序把文档里的节点串起来。这不是新设计，是白皮书已有闭环的合并读法。

```text
T-7d  内容场
      MCN 主号 / 商户职人 / KOL / 数字人闲时讲解
      → 短视频、直播、LED 预告
      → 兴趣停留在货盘，而不是停在观看数

T-0   到场（流量链入口）
      停车 / 入口 CV / 会员或学生身份
      → L1 感知：这是谁（师生/居民/酒店/家长）？从哪来？
      → 进不了 OneID 的人，只能被统计，不能被召回

T+min 逛与停（人—场匹配）
      热力 + 动线 + 导航 + 夜场/广场活动
      → 冷区用内容/券/活动临时加热（v0.6 新规则）
      → 峰值走湖滨式三色预警：调铺建议 + 疏散预案，不是看热闹

T+min 转化（交易链）
      画像发券 / 动态定价 / 酒店餐饮娱乐联票
      → 执行层必须打到 POS 与核销码
      → 没有核销，内容投放不算完成

T+h   夜场主战场
      舞台 + LED + 摊位 + 安保 同一指挥链路
      → 夜场坪效是流量链的加速器，不是另开的活动预算

T+1d  回流与再训练（L5 归因）
      核销、客单、停留、复购、能耗、工单
      → 回到数据中台
      → 再训练发券、排班、投流、调铺
      → 商户侧数据若不上报，画像在此断链（最高频失败点）
```

场景优先级函数（v0.1 §5）：

> 优先级 = ROI × 可行性 × 窗口紧迫性 × 对其他场景的数据反哺系数

因此 P0 不是「功能最多」，而是 **能反哺别的场景的流量节点**：客流洞察、内容矩阵、能耗、智能营销、招商 AI、夜经济 AI、MCN、教育集群。决策沙盘（P2）故意后置——没有真实回流数据会空转。

## 6. 开业前九个月：流量路径的施工顺序

窗口：2026.08 → 2027.05.01（v0.1 编制基准）。错过这个 When，以后付的是改造税和组织重训税（v0.6 §5.4）。

```text
M1  战略定调 + 数据中台 POC + 招商AI启动
    → 锁：核销 API、客流 API、商户数据义务条款
M2  智能硬件招标 + MCN 工位预订
M3  数字人试跑 + KOL 签约          ← 内容场开始有产能
M4  CV+能耗安装 + MCN 试运营       ← 感知四肢 + 内容核
M5  营销AI内测 + MCN 正式          ← 增长循环可跑小样本
M6  数据中台上线 + BI v1
M7  商户AI培训 + 全系统联调        ← 节点网络必须在此时接通
M8  试营业复盘 + 5.1 活动策划
M9  5.1 开业：经营系统亮相，不是功能展览
```

架构含义（v0.1 §8）：M1–M4 锁死基础层与 MCN；M5–M7 跑通增长循环；M8 联调；M9 用 L2 执行能力开业。

数据中台 POC 的验收物必须含 **核销与客流 API**（v0.5 行动清单）。只有大屏、没有这两类 API，等于流量路径在 L1 封顶。

## 7. 路径会在哪里断（对照表）

| 断点 | 文档原话/位置 | 结果 | 对策（文档已写） |
|------|----------------|------|------------------|
| 有热力无动作 | 失败模式 L0–L1；闭环原则 | 流量看见了，调不了铺 | 客流 P0 产出定义为调铺/排班/投放 |
| 有会员无跨业态归因 | v0.1 §1.2 | 交易链算不清联单 | OneID + 统一 POS |
| 有投放无核销 | v0.1 §1.2；内容链飞轮 | 钱停在曝光 | 总部级货盘/核销中台 |
| 商户不报数 | v0.1 风险表；组织原则 | 画像断链，精准流量发不出去 | 合同义务 + 激励对冲 |
| 内容外包、MCN 不当中台 | v0.1 §3.1 分叉 | 内外错配消不掉 | MCN 做利润中心 |
| 跳过数据中台上大脑 | 分层原则；先四肢后大脑 | 演示型 AI | 禁止无数据基础上「AI 大脑」 |
| 三场分裂 | v0.6 §6.2 | 热闹、热力、带货互不相干 | 同一编排逻辑 + 回流原则 |
| 决策 AI 过早上 | P2 后置 | 无真实样本空转 | 开业 6 个月后再做沙盘 |

## 8. 并列路径：智算云 Token 请求流

来源：`trae/agent-DBLvD5/index.html`（标题：智算云 - 面向 Agent 时代的智能 Token 工厂）。  
这条路处理的是 **模型调用**，不是街区客流。单独记下，避免和流量链混用「路径」一词。

```text
用户请求（无需指定模型）
    → 语义分析（识别任务类型与复杂度）
    → 智能路由（匹配模型资源）
    → 结果输出（高质低成本）
```

路由分层：

| 级别 | 任务 | 路由目标 |
|------|------|----------|
| Level 1 | 天气、简单问答、格式转换 | 轻量模型（低成本、低延迟） |
| Level 2 | 代码解释、文档摘要、翻译 | 标准模型 |
| Level 3 | 法律审查、医疗诊断、复杂推理 | MoM 混合模型融合 |

产品层还有：大语言模型 API、智能模型网关、Agent 云服务、GPU 云服务。  
与 XLOOP 的唯一概念交集是「内容生成 / Agent 会调用模型」；**不要把 Token 路由画进客流动线图。**

Xpark 招商站（`trae/agent-CY6Wjw`）只有获客表单与政策展示，没有可抽取的流量系统路径。

房地产「零现金启动化债路径」是以房抵债、过户、缴配套费的权利流，与本节客流无关。

## 9. 读完以后应记住的操作含义

1. **流量入口有两个：** 场内 CV/停车/身份，以及场外 MCN 内容。只建其中一个，路径不完整。  
2. **流量出口不是大屏，是核销、调铺、排班、投放、联票。** 没有执行层，路径在 L1 死亡。  
3. **回流是路径的一部分，不是报表附件。** 商户不上报、POS 不统一、核销 API 不进 POC，下一次投放就是盲打。  
4. **分层先于放大。** 师生 / 居民 / 酒店 / 家长走不同出口；寒暑假与夜场用反潮汐，而不是同一套排班硬扛。  
5. **施工顺序不可颠倒：** 数据预埋 → MCN 产能 → 营销核销 → 客流反哺 → 业态决策。
