## 2. 锁定的经营路径

施工顺序（白皮书 v0.1 §4.2，不可颠倒）：

```text
数据预埋 → MCN产能 → 营销核销 → 客流反哺 → 业态决策
```

客人怎么走（合并读法，不是新发明）：

```text
线上种草（MCN/内容场）
        ↓
来 → 匿名计数（雷达 L1）→ 可识别才进样本（会员/学生/酒店）
  → 逛/停（热力+动线）→ 券/联票 → 核销 → OneID 回流 → 再训练
```

四条链必须同时在，流量链单独不赚钱：

| 链 | 飞轮 | 本版硬件对应 |
|----|------|----------------|
| 流量链 | 感知 → 动线 → 夜场 → 复访 | A1/A2 雷达 + A3 对照 |
| 内容链 | 生产 → 投流 → 核销 → 续费 | 不在本批硬件里，但核销 API 必须和客流 API 一起进中台 POC |
| 交易链 | 券 / 定价 / 联票 | 雷达不参与；POS/会员后接 |
| 资产链 | 招商 → 坪效 → 汰换 | 热力给调铺，不给收租大屏 |

开业锚定 **L2 执行型**：券、工单、LED、安保能下发。L0 大屏不算完工。

P0 客流洞察的产出锁成三样（白皮书 v0.5 湖滨启示）：**调铺建议、夜场安保预案、招商画像**。没有这三样，设备等于没装。

## 3. 锁定的感知架构

```text
        室内 60G 吸顶雷达          室外 60G 热力雷达
        （进出 / 区域人数）        （广场 / 夜市网格）
                 \                    /
                  \                  /
                   边缘网关（缓存 ≥24h）
                            │
                    数据中台 客流 API
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
           调铺/排班     夜场安保       投放/核销对照
                            │
              入口 CV（同断面）只做人工/算法校准
              身份分层走会员·学生证·酒店，不走雷达
```

点位编码（贴机身、进网关、进中台，三处同名）：

| 编码 | 设备 | 位置 | 主指标 |
|------|------|------|--------|
| `IN-MAIN-E` | A1 | 主入口东 | in/out |
| `IN-MAIN-W` | A1 | 主入口西 | in/out |
| `IN-SEC` | A1 | 次入口 | in/out |
| `ESC-3F` | A1 | 3# 扶梯口（可改楼号） | up/down |
| `PLZ` | A2 | 中心广场 | region + heat |
| `NIGHT` | A2 | 夜市 | region + heat |
| `IN-MAIN-CAM-E` | A3 | 主入口东对照 | in/out 校准 |
| `IN-MAIN-CAM-W` | A3 | 主入口西对照 | in/out 校准 |

主入口净宽 **>4 m 必须 2 台**，已按 2 台锁进首批。量完若 ≤3.5 m 且无中柱，可把 `IN-MAIN-W` 改备件，不改版本号，只改附录 A。

## 4. 锁定的首批采购（现在就按这个买）

对经销商只许用这段话：

> 街区客流 POC：4 台室内 60G 吸顶客流雷达（进/出+区域人数），2 台室外热力雷达（IP65），2 台客流摄像机做同断面对照。PoE 或书面供电方案。开放 HTTP/MQTT/SDK，私有化对接，不接受只能看你们云的方案。报价须带型号、API 文档、到场标定、质保。不要报车检雷达、防砸雷达、24G 照明雷达、人体存在开关。

| 序号 | 物品 | 数量 | 锁定条件 |
|------|------|------|----------|
| A1 | 60G 室内吸顶客流雷达 | 4 | 层高 2.8–6 m；覆盖半径 ≥4 m；进/出分离；PoE |
| A2 | 60G 室外/半室外热力雷达 | 2 | IP65；网格人数或热力；夜用 |
| A3 | 双目或鱼眼客流摄像机 | 2 | 与主入口雷达同断面；PoE；开放协议 |
| B1 | ≥8 口工业 PoE 交换机 | 2 | 802.3af/at；千兆 |
| B2 | 超五类/六类网线 + 室外阻水线 | 2 箱 | 单段 ≤90 m；按实测加 20% |
| B3 | 原厂吸顶/壁装支架 + 防水箱 | 与设备 1:1 | 雷达前方无金属遮挡 |
| B4 | 边缘网关（可跑 Docker） | 1 | 能转中台 API；断网缓存 ≥24 h |
| B5 | 施工包（12V 备电、水晶头、标签） | 1 | — |

**首批明确不买：** 车检/防砸雷达、智慧大屏、城市指挥舱、闭源客流云年费、大路数 NVR、每 200㎡ 盲补的雷达。

询价带（不是合同价）：室内雷达 1.5–6 千 / 台，室外热力 4 千–2 万 / 台，客流相机 2–8 千 / 台。硬件合计常见 **3–8 万**。超过 15 万且无 API 文档，换供应商。

二期才谈：停车人行口 1 台客流雷达、3# 各层通道、4# 大堂、7# MCN 入口、冷区试验点。没有平面图不许按面积摊。

## 5. 锁定的中台合同（没有这些字段 = POC 失败）

网关对中台只保证下面四个业务字段。厂商原名可以不同，必须能映射过来。时间统一 **Asia/Shanghai**，点位名用 §3 编码。

```json
{
  "point_id": "IN-MAIN-E",
  "ts": "2026-08-25T19:05:00+08:00",
  "in_count": 12,
  "out_count": 9,
  "region_count": 86,
  "dwell_seconds": 210,
  "heatmap": [[0.1, 0.2, 0.8]]
}
```

| 字段 | 谁必须有 | 用途 |
|------|----------|------|
| `in_count` / `out_count` | A1、A3 | 来 |
| `region_count` | A2，A1 能出也要出 | 停 |
| `dwell_seconds` | 能出的都出 | 停得住不住 |
| `heatmap` 或轨迹点 | A2 必出 | 动线 / 冷热区 |

数据中台 POC 和客流硬件 POC **同一周验收**：有数字、有核销 API 占位、没有大屏，也算过。只有大屏、没有这两类 API，判失败。

## 6. 锁定的准确率

白皮书口径是客流洞察 70%→98%。本版把它拆成可执行台阶，避免到货第一天就按 98% 退货。

| 阶段 | 口径 | 怎么验 |
|------|------|--------|
| 桌面通电 | 有进/出变化即可 | 手在雷达下走 20 次 |
| 装上主入口当天 | 与人工点算误差 ≤15% | 来回 50 趟 |
| POC 结束（校准周） | ≥85% | 7 天 × 午/晚/夜 各 15 分钟 |
| 开业（L2） | ≥95% | 抽测 + 对照相机 |
| 开业 12 个月内 | 冲 98% | 和画像分层一起算，不单考雷达 |

误差 >15%：先改高度、虚拟线、灵敏度，**先不换品牌**。连续两天改参数仍 >20%，再换货。

## 7. 锁定的安装日历（到货后按天，对齐 M1–M4）

白皮书：M1 锁客流 API，M2 硬件招标，M4 安装感知。本批硬件到货后按下面 7 步，不许第一天满场开孔。

**第 0 天 · 开箱（30 分钟）**  
点名 A1×4、A2×2、A3×2、B1–B5。按 §3 贴编码。要说明书、默认 IP、账号、MQTT topic、OpenAPI。缺 API 文档停工。

**第 1 天 · 桌面通电**  
同一网段改密码，关掉公有云强制绑定。每台走 20 步；`curl` 或 MQTT 能看到 §5 JSON。不合格当场退。

**第 2 天 · 主入口第一对**  
`IN-MAIN-E` + `IN-MAIN-CAM-E` 同断面。高度 3.0–3.5 m，门洞正上，前方无金属/灯箱/喷淋。虚拟进线、出线盖满门宽。人工 50 趟，先过 ±15%。

**第 3 天 · 主入口西 + 次入口 + 扶梯**  
`IN-MAIN-W`、`IN-SEC`、`ESC-3F`。扶梯统计上楼/下楼，不斜射踏板。时区、日切与主入口相同。

**第 4 天 · 广场 + 夜市**  
`PLZ`、`NIGHT`。杆或檐下 4–8 m，避开 LED 正后方。网格：舞台前、摊位区、通道。19:00–21:00 看冷热区是否分得开。

**第 5 天 · 进中台**  
四字段进数据中台。下游只接调铺草稿和夜场安保草稿。禁止以大屏亮相作为完工仪式。

**第 6–12 天 · 校准周**  
按 §6 抽测。稳定后再谈二期数量。

## 8. 锁定的断点（再出现就按这张表修）

| 现象 | 判定 | 修法 |
|------|------|------|
| 有热力，调不了铺 | 停在 L1 | 本周必须出一页调铺建议，哪怕是人工写 |
| 有投放，无核销 | 内容链断 | 核销 API 与客流 API 绑在同一次 POC |
| 想用雷达认师生 | 越权 | 加会员/学生身份，雷达保持匿名 |
| 供应商只给云账号 | 合同不合格 | 退货或补私有化接口，否则停装 |
| 第一天全场打孔 | 施工违纪 | 退回第 1 天桌面通电 |
| 先上决策沙盘 | P2 提前 | 开业 6 个月后再做 |
| 商户不报 POS | 画像断链 | 招商合同写数据义务 + 激励 |

## 9. 明确不锁（改这些不叫推翻 v1.0）

- 经销商最终型号字符串（只要满足 §4 条件）  
- 主入口实测门宽、层高导致的 2 台 / 1 台微调  
- 扶梯编码里的楼号（`ESC-3F` 可改 `ESC-7F`）  
- 二期点位数量  
- 内容矩阵、MCN 招商、能耗策略的细案（仍以白皮书为准，不在本文扩写）  
- 智算云 Token 路由、房地产化债（不是客流）
