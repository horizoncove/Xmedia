# 客流雷达：先买什么，回来怎么装

> 工作底稿。与 [最终版 v1.0](../zhidaoflow/XLOOP_感知与流量路径_最终版_v1.0.md) 冲突时以最终版为准。首批已剔除停车车检雷达（原 A4）。

**用途：** 下单用，到货后按第 4 节一步一步装。  
**依据：** 白皮书把感知点位锁在入口、扶梯、广场、停车场；客流热力必须能驱动调铺 / 排班 / 投放，否则不上线。  
**原则：** 先买能出 API 的感知四肢，不买只能看大屏的套装。

---

## 0. 现在就做的决定

买 **60GHz 毫米波客流雷达** 做人数、进出、热力；入口再配 **双目/鱼眼客流摄像机** 做校准，不要拿交通测速雷达或道闸防砸雷达当客流设备。

海康 `DS-TMG035/60G` 是车辆出入口雷达，**不要买进客流清单**。停车人流二期另配客流雷达，不占用首批名额。

首批只覆盖「能证明数据中台吃得下客流 API」的最小闭环。开业全量等点位图复核后再加。

## 1. 下单清单（首批 POC）

对经销商直接说这四句：

1. 要 **60G 吸顶客流雷达**，不是人体存在开关、不是 24G 照明雷达、不是车检雷达。  
2. 必须输出：**进 / 出人数、区域人数、停留、轨迹或热力**，开放 **HTTP / MQTT / SDK**，能自己拉取，不绑死对方云。  
3. 室内 **PoE**；广场 / 夜市 / 停车 **IP65 + 宽温**。  
4. 合同写清：准确率验收口径、API 文档、至少 3 个测试账号、到场标定 1 次。

| 序号 | 买什么 | 数量 | 装哪里 | 必须满足 | 典型询价方向（到店核对现货型号） |
|------|--------|------|--------|----------|----------------------------------|
| A1 | 60G 吸顶客流雷达（室内，进出+区域人数） | 4 | 主入口 2、次入口 1、扶梯口 1 | 层高 2.8–6 m；覆盖半径 ≥4 m；进/出分离；PoE | 60G 轨迹人数雷达（希卡立 L7 Pro 类、迈睿 60G 客流款、海凌科/云里物里工规款） |
| A2 | 60G 广域热力雷达（室外/半室外） | 2 | 中心广场 1、夜市 1 | IP65；热力或网格人数；能夜间工作 | 室外 60G 区域人数 / 热力雷达 |
| A3 | 双目或鱼眼客流摄像机（校准用） | 2 | 与主入口雷达同断面 | 进出统计；吸顶；PoE；开放协议 | 海康客流鱼眼（如 DS-2CD6365 系列「人数统计/倾斜客流」款）或大华同级 |

| B3 | 吸顶盒 / 壁装支架 / 防水箱 | 与设备 1:1 | 每个点位 | 雷达前方无金属遮挡 | 跟雷达原厂支架买，少用杂牌万向节 |

**先不要买：** 智慧大屏、城市级指挥舱、厂商闭源「客流云年费」、超过 16 路的 NVR（雷达不是录像机业务）。

询价话术（复制给供应商）：

> 我们要街区客流感知 POC：4 台室内 60G 吸顶客流雷达（进/出+区域人数），2 台室外热力雷达，2 台客流摄像机做对照。全部要 PoE 或明确供电，开放 HTTP/MQTT/SDK，私有化对接，不要只能看你们云平台的方案。请报型号、单价、API 文档、标定服务、质保。

## 2. 点位和流量路径怎么对上

```text
主入口雷达+摄像机 ──来──▶ 进/出人数
次入口 / 扶梯雷达 ──逛──▶ 楼层转换、动线
广场 / 夜市热力   ──停──▶ 停留与峰值（夜场主战场）
停车雷达          ──来源──▶ 车流辅助，不替代人流
        │
        ▼
边缘网关 → 数据中台客流 API → 调铺 / 排班 / 投放
```

白皮书里的三层客流（师生 / 居民 / 酒店）雷达本身分不出来，必须后面和会员 / 身份券对齐。雷达只负责 L1：人头准、进出准、热力在。

## 3. 下单前 10 分钟核对

- [ ] 现场层高：室内天花是否在 2.8–4.5 m（超 6 m 要换广域款）  
- [ ] 主入口净宽：超过 4 m 就按 2 台对打或加 1 台，不要 1 台硬扛  
- [ ] 广场 / 夜市有没有现成弱电和立杆（没有就加立杆和防水箱）  
- [ ] 弱电间到各点是否已预埋管，没有就先买管材再买设备  
- [ ] 供应商能当场演示：浏览器或 MQTT 看到进/出数字  

价格心里有数（2026 询价带，以经销商报价为准，不作合同价）：

| 品类 | 单台常见带 |
|------|------------|
| 室内 60G 客流雷达 | 约 1.5–6 千 |
| 室外热力雷达 | 约 4 千–2 万 |
| 客流鱼眼/双目 | 约 2–8 千 |
| 8 口 PoE | 约 8 百–2 千 |

首批硬件（不含施工）大致落在 **3–8 万**。超过 15 万还没 API 文档，换供应商。

## 4. 到货后怎么装（一步一步，后面按这个带）

货到先拍照留档，**不要当天全场开孔**。按天做。

### 第 0 天：开箱核对（30 分钟）

1. 按第 1 节表格点名：A1×4、A2×2、A3×2、网关、交换机。  
2. 每台贴标签：`入口-主-东`、`入口-主-西`、`入口-次`、`扶梯-3#`、`广场`、`夜市`。  
3. 向供应商要：说明书 PDF、默认 IP、账号、MQTT topic、OpenAPI 地址。  
4. 缺 API 文档就停，先别打孔。

### 第 1 天：桌面通电（半天，弱电间桌子上）

1. 交换机上电，电脑和 1 台雷达进同一网段。  
2. 浏览器打开默认 IP，改密码，关掉公有云强制绑定。  
3. 用手在雷达下走过 20 次，确认进/出计数会变。  
4. 用 `curl` 或 MQTT 客户端拉到一条 JSON。网关能收到，才算这台合格。  
5. 4+2 台都过一遍，坏的当场退换。

### 第 2 天：主入口装第一对（雷达 + 摄像机对照）

1. 装在门洞正上方，雷达朝下，前方无金属牌、灯箱、喷淋挡波。  
2. 高度优先 3.0–3.5 m；俯角按说明书，常见 0° 吸顶或 10–20° 斜装。  
3. 画虚拟过线：进店一条、出店一条，线要盖住整门宽。  
4. 同一断面装对照摄像机，只为验收，不替代雷达。  
5. 拉人来回走 50 趟，雷达与人工点算误差目标先到 **±15%**，再调到白皮书要的 70%→98% 路径上（先 85%，再 95%）。

### 第 3 天：次入口 + 扶梯

1. 扶梯口装在楼层转换处，统计「上楼 / 下楼」，不要对着扶梯踏板斜射。  
2. 和主入口用同一套主题和时区，避免两套日切。  
3. 进网关，点位名与第 0 天标签一致。

### 第 4 天：广场 + 夜市热力

1. 杆高或檐下 4–8 m，避开 LED 大屏正后方（电磁和遮挡）。  
2. 画 3 个网格：舞台前、摊位区、通道。  
3. 晚上 19:00–21:00 做一次峰值走查，热力要能看出冷区 / 热区，这才能给调铺和安保。

### 第 5 天：进中台，不进大屏

验收只认这四条 API（名称可按厂商字段映射）：

| 接口 | 用途 |
|------|------|
| `in_count` / `out_count` | 入口进出 |
| `region_count` | 广场/夜市实时人数 |
| `dwell_seconds` | 停留 |
| `heatmap` 或轨迹点 | 动线 / 冷热区 |

接到数据中台后，**先接调铺建议和夜场安保，不接宣传大屏**。大屏可以后做。

### 第 6 天：校准周

连续 7 天，每天 3 个时段（午、晚、夜）人工抽 15 分钟：

- 记下人工人数、雷达人数、误差  
- 误差 >15%：改高度、虚拟线、灵敏度，不要先改算法供应商  
- 稳定一周，再决定开业扩容数量
